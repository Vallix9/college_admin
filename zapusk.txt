Подробная инструкция по запуску проекта College Admin
(Windows; команды PowerShell или cmd, ActivateScript отличается только путём)

Проект — веб-приложение для автоматизации учёта студентов и успеваемости
в колледже: Flask, SQLite, pandas, Excel-выгрузка.

===============================================================================
1. ТРЕБОВАНИЯ
===============================================================================
- Windows 10/11 (в Docker — любой Linux-хост с Docker)
- Python 3.9 или новее (проверено на 3.13)
- Доступ к командной строке
- Для Docker-варианта: Docker Desktop с docker compose (Compose v2)

===============================================================================
2. ПОДГОТОВКА
===============================================================================
Распакуйте проект в отдельную папку, например:
    D:\programmirovanie\college_admin\college_admin
В этой папке должны лежать run.py, app\, requirements.txt, .env.example.

Откройте командную строку и перейдите в папку проекта:
    cd D:\programmirovanie\college_admin\college_admin

===============================================================================
3. ВИРТУАЛЬНОЕ ОКРУЖЕНИЕ
===============================================================================
Создайте окружение:
    python -m venv venv
Если Python 3.11+, команда может называться python3 или py -3.11.

Активируйте:
    PowerShell:  .\venv\Scripts\Activate.ps1
    cmd:         venv\Scripts\activate
В начале строки появится (venv). Если PowerShell ругается на политику запуска
скриптов:
    Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass

===============================================================================
4. ЗАВИСИМОСТИ
===============================================================================
    pip install -r requirements.txt

Только для разработки и тестов (добавляет pytest):
    pip install -r requirements-dev.txt

Актуальные версии пакетов зафиксированы в requirements.txt:
Flask 3.0.3, Flask-SQLAlchemy 3.1.1, Flask-WTF 1.2.1, Flask-Login 0.6.3,
SQLAlchemy 2.0.36, pandas 2.2.3, openpyxl 3.1.5, waitress 3.0.0.

===============================================================================
5. НАСТРОЙКИ (.env)
===============================================================================
Скопируйте пример и отредактируйте под себя:
    PowerShell:  Copy-Item .env.example .env
    cmd:         copy .env.example .env

Обязательное для production (для локального запуска можно оставить как есть):
    SECRET_KEY=            случайная строка не короче 32 символов
                            python -c "import secrets; print(secrets.token_hex(32))"
    ADMIN_PASSWORD=        пароль первого администратора

Необязательное, но полезное:
    HOST=127.0.0.1         адрес прослушивания
    PORT=5000              порт
    DATABASE_URL=sqlite:///college.db
FLASK_DEBUG=1          сервер разработки с автоперезагрузкой (только для
                           локальных адресов: 127.0.0.1, localhost, ::1)
    FLASK_DEV_SERVER=1     принудительно Werkzeug, даже если отладка выключена
    APP_ENV=production     включает проверки production (SECRET_KEY, пароль)
    TZ=Europe/Moscow      часовой пояс для дат в базе и журналов
    BACKUP_FOLDER=backups, EXPORT_FOLDER=exports, LOG_FOLDER=logs,
    UPLOAD_FOLDER=uploads
    COOKIE_SECURE=1        метка Secure у cookie (для работы через HTTPS)

Файл .env не коммитится (он в .gitignore). Файл .env.example — безопасная копия
без секретов.

===============================================================================
6. БАЗА ДАННЫХ И ПЕРВЫЙ АДМИНИСТРАТОР
===============================================================================
Схема (создание таблиц, добавление новых колонок и уникальных индексов):
    python migrations.py

Начальное наполнение (период, группы, предметы, несколько студентов) и
создание администратора по ADMIN_USERNAME / ADMIN_PASSWORD:
    python init_db.py

Создать ещё одного администратора. Сброс пароля существующему: задайте
RESET_ADMIN_PASSWORD=1 и его ADMIN_USERNAME, затем запустите скрипт ещё раз:
    python create_admin.py

По умолчанию, если в .env ничего не задано: логин admin, пароль admin123.
В production так оставлять нельзя — приложение само откажется стартовать с
паролем из .env.example и ключом dev-secret-key-123.

===============================================================================
7. ЗАПУСК
===============================================================================
    python run.py

По умолчанию http://127.0.0.1:5000. Адрес и порт берутся из .env (HOST, PORT).

Что именно запустится, решает режим отладки:
- FLASK_DEBUG=1 (или FLASK_DEV_SERVER=1) — сервер Flask с автоперезагрузкой,
  только для локальных адресов;
- иначе — waitress, как в production.

Другой порт без правки кода:
    PowerShell:  $env:PORT = 5001; python run.py
    cmd:         set PORT=5001 && python run.py
или впишите PORT=5001 в .env.

===============================================================================
8. ПЕРВЫЙ ВХОД
===============================================================================
Откройте http://127.0.0.1:5000 — откроется /login.
Войдите как администратор, затем проверьте по порядку:
- /periods — создать учебный период (иначе итоги и часть отчётов будут пустыми);
- /subjects, /groups — предметы и группы;
- /staff — преподаватели (логин — фамилия латиницей);
- /schedule — расписание и там же отметки «занятие было»;
- /journal — сетка журнала, оценки и пропуски;
- /students/add — студенты, /accounts — выдача им паролей.

Как вести журнал, считаются итоги и что видит студент — в ДОКУМЕНТАЦИЯ.md.

===============================================================================
9. ТЕСТЫ
===============================================================================
    pytest                    весь набор (94 проверки)
    pytest tests/test_data.py один файл
    pytest -k backup          выборочно по имени теста

Тесты не трогают рабочие данные: tests/conftest.py собирает эталонную базу в
одном файле и перед каждым тестом копирует её в отдельную рабочую базу во
временном каталоге. Коллекция ограничена файлами test_*.py (pytest.ini),
поэтому автономные phase*_test.py не запускаются.

Отдельные скрипты-проверки прошлых фаз запускаются вручную:
    python phase14_test.py    права, CSRF, заголовки (105 проверок)
    python roles_test.py     матрица ролей
    python smoke_test.py     основные сценарии
    python check_export_match.py  выгрузка соответствует базе
Эти скрипты печатают отчёт и вызывают sys.exit(main()) — pytest их не видит.

===============================================================================
10. DOCKER
===============================================================================
    copy .env.example .env      заполнить SECRET_KEY и ADMIN_PASSWORD
    docker compose up -d --build
    docker compose logs -f web

Контейнер работает под пользователем college (uid 1000), не от root, и
использует waitress. Схема базы создаётся при старте
(python migrations.py && python run.py), поэтому первый запуск на пустом томе
работает. Тома: college_data (college.db), ./backups, ./exports, ./logs.
По умолчанию порт берётся из .env (PORT, по умолчанию 5000) и используется
с обеих сторон: хост:контейнер.
Первый администратор:
    docker compose exec web python create_admin.py

Остановить: docker compose down. Данные в томе college_data переживают
остановку и пересборку образа (но не docker compose down -v).

11. РЕЗЕРВНОЕ КОПИРОВАНИЕ ВРУЧНУЮ
===============================================================================
Остановите приложение (Ctrl+C) и скопируйте college.db целиком.
Собственные копии: /settings/backup — архив в backups/, восстановление
из архива доступно там же (перед восстановлением текущая база сохраняется
в pre_restore_*.db).

12. ВОЗМОЖНЫЕ ПРОБЛЕМЫ
===============================================================================
"Can't locate label: No module named 'app'"
    Вы не в папке проекта (где лежит run.py). Вернитесь туда через cd.

"Could not build url for endpoint ..." / страница 500 при входе
    База не создана: python migrations.py, затем python init_db.py.

Не запускается: "SECRET_KEY ..." или "пароль ... из .env.example"
    В .env остались значения-примеры. Задайте свои:
    python -c "import secrets; print(secrets.token_hex(32))" и свой
    ADMIN_PASSWORD.

Порт 5000 занят
    Порт занят (часто WSL). Смените PORT в .env, например 5001.

Не скачивается выгрузка, не создаётся бэкап
    Каталог недоступен для записи. В обычном запуске он создаётся сам
    (exports/, backups/, logs/, uploads/). В Docker проверьте, что каталоги
    на хосте принадлежат пользователю колледжа и в .env задан TZ.

Журнал пуст
    Нет подтверждённых дат занятий. Отметьте их: /schedule → даты занятий.

Итоги пустые
    Не выбран период (или он не создан) и группа.

"Адрес отклонён" при отправке формы
    Истёкший CSRF-токен: обновите страницу и отправьте форму ещё раз.

Забыт пароль администратора
    python create_admin.py с новым ADMIN_PASSWORD создаст ещё одну учётную
    запись. Либо RESET_ADMIN_PASSWORD=1 в .env и запустите create_admin.py
    повторно для смены пароля существующего администратора.
